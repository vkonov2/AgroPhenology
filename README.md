Репозиторий содержит несколько разделённых исследовательских контуров. Исходный
контур ретроспективно проверяет дату фенологической стадии по исторической
температуре воздуха и сумме эффективных температур (СЭТ); в нём нет ML или
оперативного прогноза. Отдельный локальный контур по фитофторозу картофеля
проверяет своевременность раннего предупреждения, включает замороженные
CatBoost-модели и готовит теневое проспективное логирование без реальной
рассылки. Его актуальная документация находится в
[`docs/research/late_blight_early_warning/`](docs/research/late_blight_early_warning/README.md).

Два новых локальных контура проверяют раннее предупреждение первой регистрации
личинки яблонной плодожорки и парши яблони. Они используют общий причинный
календарь решений, rolling-origin проверку, CatBoost и последовательную
политику уведомлений, но имеют раздельные мишени и специализированные признаки.
Итог первого цикла, включая отрицательный результат парши, приведён в
[`APPLE_TARGETS_FIRST_CYCLE_REPORT_2026-09-20.md`](docs/research/orchard_early_warning/APPLE_TARGETS_FIRST_CYCLE_REPORT_2026-09-20.md).

Запуск в новый пустой каталог:

```bash
agro-codling-moth-early-warning run --run-id <new_run_id>
agro-apple-scab-early-warning run --run-id <new_run_id>
```

Реальные VAAD-прогоны требуют локального приватного пакета входов в
`docs/extra/vaad_pipeline_repro_20260905/`. Этот каталог, исходные наблюдения,
точные координаты, погодные выгрузки и каталоги `results/` намеренно не
публикуются в Git. Чистый клон позволяет проверить код и тесты, но не повторить
полевой эксперимент без отдельно полученных разрешённых входов.

Первая конфигурация проверяет массовое отрождение гусениц яблонной плодожорки: базовая температура `10 °C`, порог `230 °C·day` (градусо-суток). Параметры находятся в конфигурации, а не в вычислительных функциях. Результат показывает ожидаемое фенологическое окно для планирования мониторинга; он не прогнозирует численность вредителя и не является рекомендацией по обработке.

## Наблюдения

Notebook принимает CSV и XLSX тремя способами: локальный путь, `google.colab.files.upload()` или путь на Google Drive. В конфигурационной ячейке задаются `INPUT_MODE`, путь и явный словарь `COLUMN_MAPPING`. Неоднозначные названия столбцов автоматически не угадываются.

Обязательные канонические поля:

Рекомендуется передавать `observation_id` и `accumulation_start_date`. Если дата начала отсутствует, её нужно явно задать общей настройкой; иначе строка исключается. ## Режимы notebook

По умолчанию notebook выполняет полностью автономную техническую демонстрацию на синтетических наблюдениях и синтетической погоде (`USE_LIVE_OPEN_METEO = False`). Это нужно для проверки с нуля без сети и не является исследовательским результатом. Для реальной ретроспективной проверки загрузите реальные наблюдения, задайте начало накопления и включите `USE_LIVE_OPEN_METEO = True`; тогда используется только Open-Meteo Historical Weather API, `models=era5_land`.

Результаты записываются в `results/validation_records.csv`, `summary_metrics.csv`, `excluded_records.csv`, `methodology.json` и `results/plots/*.png`, после чего упаковываются в ZIP. Большие кеши и результаты исключены из Git.

## Нерешённые научные вопросы

- ERA5-Land — реанализ, а не измерение микроклимата сада.
- Начало накопления СЭТ — отдельная документируемая гипотеза.
- Дата осмотра может не совпадать с точным моментом наступления стадии.
- Стадии, регионы, поколения и виды требуют раздельной проверки.
- СЭТ не оценивает плотность популяции и не доказывает необходимость применения пестицида.

Методика и решение по источнику погоды описаны в [docs/methodology.md](docs/methodology.md) и [docs/open_meteo_decision.md](docs/open_meteo_decision.md).

## Отдельный пилот по фитофторозу картофеля

Notebook [late_blight_pilot_validation.ipynb](notebooks/late_blight_pilot_validation.ipynb) считает два независимых погодных индикатора по двум ограниченным сообщениям 2026 года: Hutton Criteria и упрощённую 10-дневную модель Полякова. Этот контур не смешан с фенологической СЭТ-моделью яблонной плодожорки.

Для положительного сообщения добавлена координата деревни Бунятино `56.4008889, 37.2483611`; она считается координатой населённого пункта, а не подтверждённой координатой поля. Для отрицательной записи по-прежнему используется явно маркированный прокси центра Сергиева Посада. Автор данных подтвердил фенофазу бутонизации и региональный интервал её наступления `15–30.06.2026`. Точная полевая дата неизвестна, поэтому Поляков рассчитывается для каждого из 16 возможных дней активации без выбора или голосования между сценариями.

Погодный профиль составной и фиксируется для каждой переменной: температура и относительная влажность — `models=era5_land`, осадки для Полякова — отдельный `models=era5` запрос. Ряды объединяются только при точном совпадении локальных почасовых меток; координаты ячеек и кеши источников сохраняются раздельно. На двух сообщениях accuracy, sensitivity и specificity не рассчитываются. Подробности и текущий пилотный результат приведены в [docs/late_blight_pilot.md](docs/late_blight_pilot.md).

## Ретроспективная проверка на VAAD

Notebook [vaad_late_blight_validation.ipynb](notebooks/vaad_late_blight_validation.ipynb)
проверяет Hutton и упрощённую модель Полякова на уровне `field_uid × season`.
Он разделяет прямые и восстановленные геопривязки, использует 2015–2022 как
development и 2023–2025 как temporal test slice. Это не untouched external
holdout: правила анализа уточнялись после знакомства с набором данных. Для
Hutton считаются внутрисезонная календарная перестановка, доля тревожных дней
до первого обнаружения (как от 1 июня, так и от первого доступного визита) и
простые календарные baseline-окна: два настроены только на development, одно
фиксированное правило покрывает июль–август. Для Полякова первичным
доступным анализом считается наблюдавшаяся точка BBCH 51 с endpoint
`activation_any__onset_any`; результат попарно сравнивается с baseline,
использующим заранее фиксированное окно `BBCH51 + 15…17 дней` без погодных
критериев.

CSV VAAD не хранится в Git: в Colab его нужно загрузить в соответствующей
ячейке или указать путь на Drive. Исходный CSV, локальные кеши и event-level
таблицы (`hutton_events.csv`, `polyakov_events.csv`, `negative_seasons.csv`,
`weather_metadata.csv`) содержат идентификаторы и/или точные геопривязки — их
нельзя публиковать или включать в общий архив. Для передачи предназначены
только агрегированный `summary.json` и, если сформирован, `report_ru.md`.

Локальный запуск того же расчёта:

```bash
python -m agro_phenology.vaad_validation \
  data/vaad_observations_geocoded_recovered.csv \
  --maximum-season 2025 \
  --permutations 20000
```

Результаты сохраняются в `results/vaad_late_blight/`. Отрицательные сезоны
помечены как анализ чувствительности, а не как оценка specificity: отсутствие
структурированной положительной записи не доказывает отсутствие болезни. Даже
при наличии явного отрицательного текста без стандартизированного протокола
осмотра, регулярного полного наблюдения до конца риска и данных об обработках
такой сезон нельзя считать подтверждённым true negative. Финальная ячейка
notebook создаёт отдельный aggregate-only ZIP и намеренно не добавляет в него
event-level CSV и погодные метаданные.
