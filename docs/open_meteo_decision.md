# Решение по источнику погоды

Основной источник — Open-Meteo Historical Weather API:

```text
https://archive-api.open-meteo.com/v1/archive
models=era5_land
hourly=temperature_2m
timezone=auto
cell_selection=land
temperature_unit=celsius
```

Не используются Best Match, Forecast API или Historical Forecast API. ERA5-Land выбран как воспроизводимый исторический источник с почасовой температурой, но это реанализ модельной ячейки, а не полевое измерение.

Клиент задаёт timeout, повторяет временные сетевые ошибки с exponential backoff, проверяет структуру ответа и кеширует точные исходные байты. Ключ кеша включает координаты, период, модель, переменные, часовой пояс, выбор ячейки и единицы. Sidecar-метаданные сохраняют параметры запроса, запрошенные и возвращённые координаты, высоту, часовой пояс, смещение UTC, модель, период, переменные, время получения и URL.

Дополнительные разрешённые переменные можно сохранить для будущих исследований, но текущая формула СЭТ использует только `temperature_2m`.

## Отдельный профиль пилота фитофтороза

Это решение для СЭТ не распространяется на осадки модели Полякова. Для отдельного пилота фитофтороза явно согласован составной профиль:

```text
temperature_2m, relative_humidity_2m -> models=era5_land
precipitation                         -> models=era5
```

Запрос ERA5 содержит только `precipitation`; температура из него не используется. Два ряда имеют раздельные кеши и метаданные, а объединение разрешено только при одинаковом часовом поясе и полном совпадении локальной почасовой сетки. Возвращённые координаты обеих модельных ячеек сохраняются отдельно. Подробный протокол находится в `docs/late_blight_pilot.md`.
