# Контракт входных наблюдений

Поддерживаются CSV и XLSX. Сопоставление фактических названий с каноническими задаётся явно в `COLUMN_MAPPING`; неоднозначные столбцы автоматически не угадываются.

| Колонка | Обязательность | Описание |
|---|---:|---|
| `observation_id` | рекомендуется | Стабильный идентификатор; при отсутствии создаётся `row-N` |
| `latitude` | да | Широта WGS84 от −90 до 90 |
| `longitude` | да | Долгота WGS84 от −180 до 180 |
| `observation_date` | да | Дата наблюдения, ISO `YYYY-MM-DD` предпочтителен |
| `pest_name` | да | Название вредителя |
| `observed_stage` | да | Наблюдаемая стадия; нормализуется только явным словарём |
| `accumulation_start_date` | условно | Начало СЭТ; обязательно в строке или общей настройке |
| `crop_name` | нет | Культура |
| `region` | нет | Регион для группировки |
| `source` | нет | Источник и происхождение записи |

Проверяются координаты, разбор дат, заполненность стадии и порядок дат. Дубликаты сохраняются и маркируются, а не удаляются молча. Каждая строка получает статус `accepted`, `excluded` или `error` и машинно-читаемую причину.

Строки без даты начала исключаются, если не задана ручная глобальная дата. Нецелевые и неоднозначные стадии попадают в `excluded_records.csv`. Конфиденциальные исходные выгрузки нельзя коммитить; храните их вне репозитория либо в игнорируемом `data/raw/`.
